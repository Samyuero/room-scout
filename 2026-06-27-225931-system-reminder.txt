  redirecting to localhost:3000 and not returning to the mobile app. The
  solution handles web and native platforms differently:

  Changes Made:

  1. Updated Sign-In Screen (app/(auth)/sign-in.tsx)

  - Web flow: Uses supabase.auth.signInWithOAuth with redirect to /auth/callback
  (current window redirect)
  - Native flow: Uses WebBrowser.openAuthSessionAsync with custom scheme
  roomscout://google-auth
  - Proper loading state handling for both platforms

  2. Updated Sign-Up Screen (app/(auth)/sign-up.tsx)

  - Applied identical platform-specific logic as sign-in screen
  - Maintains username setup flow after Google authentication

  3. Added OAuth Callback Route (app/auth/callback.tsx)

  - Handles Google OAuth redirect on web platform only
  - Parses access/refresh tokens from URL hash/query parameters
  - Sets session via supabase.auth.setSession
  - Redirects to app root (which checks for username completion)
  - Includes proper error handling and fallbacks

  How It Works:

  On Web:
  1. User clicks "Sign In with Google"
  2. Current window redirects to Google's OAuth page
  3. After Google authentication, user redirects to /auth/callback
  4. Callback page extracts tokens, sets session, then redirects to app
  5. App checks for username and routes to home/setup accordingly

  On Native:
  1. User clicks "Sign In with Google"
  2. Opens system browser via WebBrowser.openAuthSessionAsync
  3. After Google auth, redirects back to app via roomscout://google-auth
  4. App processes tokens from redirect URL and sets session
  5. Proceeds to username check/home screen

  Required Configuration:

  1. In Supabase Dashboard: Add https://your-domain.com/auth/callback to Google
  provider redirect URLs
  2. In Project Configuration: Ensure scheme: "roomscout" is set in app.json
  (already present)
  3. For Local Testing: Use http://localhost:3000/auth/callback as redirect URL

  This solution separates web and native authentication flows appropriately,
  ensuring web uses standard browser redirects while native maintains the
  embedded browser experience. The callback route handles the web-specific OAuth
  completion that was previously missing.

  additional adjustments?
